# 仕様書：SNS動画ダウンロード & GIF変換 PWA

- 版：v0.1（仕様確認用ドラフト）
- 利用者：本人のみ（非公開運用）
- 対象端末：iPhone（iOS 16.4 以降）/ Safari でホーム画面に追加して使用

---

## 1. 全体構成

```
[iPhone PWA]  ── HTTPS + 合言葉 ──▶  [Google Cloud Run サーバー]  ──▶  X / TikTok / Instagram
 (GitHub Pages)                        (yt-dlp + ffmpeg)
     │
     └─ GIF変換・トリミングは iPhone 内で完結（動画をサーバーへ送らない）
```

| 部品 | 置き場所 | 役割 |
|---|---|---|
| PWA（画面） | GitHub Pages（public リポジトリ・無料） | 操作画面、GIF変換、アプリ内保存、履歴 |
| ダウンロードサーバー | Google Cloud Run（東京リージョン） | URLから動画情報の取得・mp4の生成 |

リポジトリ構成（予定）：

```
web/      PWA 本体（TypeScript + Vite）
server/   Cloud Run 用サーバー（Python + FastAPI + yt-dlp + ffmpeg、Dockerfile）
docs/     仕様書など
.github/workflows/  GitHub Pages への自動公開
```

## 3. 機能仕様：動画ダウンロード

### 3.1 対象
- X（Twitter）、TikTok、Instagram（YouTube は v0.5 で対象外に変更：クラウドからのアクセスが拒否されるため）
- 公開投稿のみ（Instagram はログイン情報を使わない）

### 3.2 操作の流れ
1. URL をコピー → アプリで「貼り付け」ボタン（または入力欄に貼り付け）
2. サーバーが投稿を解析
3. **複数動画がある投稿**：サムネイル一覧から保存する動画を選択（複数選択可）
4. **画質選択**：取得可能な画質の一覧を表示。**最高画質が初期選択**、他（1080p / 720p / 480p …）も選べる
5. ダウンロード（進捗表示）→ 完了後に次のどちらかを選ぶ
   - **写真に保存**：共有シートが開き「ビデオを保存」をタップ（iOS の制約で1タップ必要）
   - **保存せず GIF へ**：写真アプリには入れず、アプリ内に保持したまま GIF 変換画面へ
   - （どちらも選ばず閉じた場合もアプリ内に保持され、履歴から後で操作可能）

### 3.3 形式・画質
- 出力は **mp4（映像 H.264 + 音声 AAC）**：iPhone の写真アプリでそのまま再生・保存できる形式
- 「最高画質」＝ H.264 で取得できる範囲の最高画質
- H.264 で提供されない画質は、一覧に「要変換・時間がかかる」と注記して表示（サーバー側で H.264 に再変換）

### 3.4 サーバー API（参考）
| エンドポイント | 内容 |
|---|---|
| `POST /api/extract` | URL → 動画一覧（サムネイル・長さ・画質一覧） |
| `POST /api/download` | URL + 動画番号 + 画質 → mp4 をストリーミング返却 |

- 全リクエストに合言葉ヘッダーが必要。合言葉は Cloud Run の環境変数で管理し、リポジトリには含めない
- CORS は GitHub Pages のドメインのみ許可
- ダウンロードした動画はサーバーに残さない（送信後に即削除）

### 3.5 既知のリスク
- Instagram はクラウドからのアクセスを遮断することがあり、一時的に取得できない場合がある（エラー時はその旨を表示）
- SNS 側の仕様変更で取得できなくなった場合は yt-dlp の更新で対応（サーバー再デプロイ）

## 4. 機能仕様：GIF変換

### 4.1 入力元
- **写真アプリの動画**：「動画を選択」から写真ライブラリの動画を選ぶ
- **アプリ内の動画**：ダウンロード済み動画（ダウンロード完了画面・履歴から「GIFにする」）

### 4.2 トリミング画面
- **サムネイル付きタイムライン**：左右ハンドルで開始・終了位置を指定
- **ピンチで拡大/縮小**：タイムラインを拡大し、1フレーム単位まで調整可能。拡大中は横スクロール
- **コマ送りボタン**：開始・終了それぞれ ◀ ▶ で1フレームずつ移動
- **数値入力**：`分:秒.xx` で直接指定
- **プレビュー**：選択範囲をループ再生。ハンドル操作中は該当フレームを即表示
- **常時表示**：選択の長さ、出力解像度、フレーム数、予測容量
- 選択範囲が **30秒を超えると警告表示**（原則30秒以内。確認すればそのまま変換も可能）

### 4.3 変換設定
| 項目 | 仕様 | 初期値 |
|---|---|---|
| 解像度 | 元動画比の % 指定（1%刻みスライダー＋ 100/75/50/25% ボタン）。実寸 `→ 640×360` を併記。縦横比は元動画を維持 | 50% |
| フレームレート | 「元のまま（上限30fps）」/ 30 / 24 / 20 / 15 / 10 fps。元が30fps未満なら水増ししない。60fps動画は30fpsに間引く | 元のまま |
| ディザリング | オン / オフ | オン |
| ループ | 無限ループ | 固定 |

### 4.4 再生速度を元動画と一致させる仕組み
- GIF の表示間隔は 1/100 秒単位のため、30fps（33.3ms）はそのままでは表現できない
- 各フレームの **元動画上の時刻から表示間隔を計算**し、`3,3,4,3,3,4…`（×10ms）のように配分して、平均を 33.3ms に一致させる
- 可変フレームレートの動画（iPhone 撮影動画など）でも、元の時刻基準で配分するため長時間でもズレが蓄積しない

### 4.5 予測容量
- 変換前に、選択範囲から数フレームを実際の設定で試し変換 → 全フレーム数から推定
- 表示例：「予測 約 18MB（15〜22MB）」
- 設定（解像度・fps・ディザ・範囲）を変えるたびに自動更新
- **20MB 超で注意表示**（しきい値は設定で変更可能）

### 4.6 変換処理
- すべて iPhone 内で処理（動画を外部に送らない）
- フレームを1枚ずつ取り出し → 縮小 → 減色 → GIF に書き出し、を逐次実行（メモリ使用を抑え、長めの動画でも落ちにくくする）
- 減色は動画全体で共通のパレットを使用（フレームごとの色のちらつきを防ぐ）
- 進捗バー（％・残り時間目安）とキャンセルボタン

### 4.7 変換後
- GIF をアプリ上で再生（ループ）
- **画像を長押し → 「写真に追加」で保存**（iOS 標準メニュー）
- 予備として「保存・共有」ボタン（共有シート経由）
- 実際のファイルサイズ・解像度・フレーム数・長さを表示
- **元動画を削除**ボタン：アプリ内の動画（ダウンロード済みで写真に保存していないもの）のみ対象
  - 写真アプリの動画は iOS の制約によりアプリから削除不可（写真アプリで手動削除）

## 5. 履歴

- ダウンロード履歴：サムネイル、元URL、SNS名、画質、日時
- GIF履歴：サムネイル、サイズ、元動画、日時
- アプリ内に保持している動画・GIF はここから「写真に保存」「GIFにする」「削除」
- 設定画面にアプリ内ストレージ使用量を表示し、まとめて削除可能

## 6. セキュリティ・運用

- サーバーは合言葉で保護（初回起動時に設定画面で入力、端末内に保存）
- Cloud Run は最小インスタンス 0（使わない間は停止、課金なし）
- **費用の目安**：処理時間は無料枠内の見込み。外部への通信量は無料枠を超えると 1GB あたり約20〜30円（例：月に 100MB の動画を20本なら約2GB）
- Google Cloud の **予算アラート**（例：月500円）を設定し、想定外の課金を検知

## 7. ご本人に Safari で行っていただく作業（手順は都度案内します）

1. GitHub：リポジトリを public にし、Settings → Pages → Source を「GitHub Actions」に変更
2. Google Cloud：プロジェクト作成・請求先（クレジットカード）登録・予算アラート設定
3. Cloud Run：GitHub リポジトリを連携してデプロイ、合言葉を環境変数に設定
4. iPhone：公開URLを Safari で開き「ホーム画面に追加」、設定画面でサーバーURLと合言葉を入力

## 9. 動画形式と変換の方針（v0.7 で実装）

### 9.1 前提
- 保存先の写真アプリ・アプリ内の再生・GIF 変換（Safari の `<video>`）のすべてで扱える形式であること
- 入れ物（コンテナ）は **mp4 のまま**（写真アプリが扱えるのは mp4 / mov。WebM は写真に保存できない）

### 9.2 コーデック別の扱い
| 映像コーデック | iPhone での扱い | 方針 |
|---|---|---|
| H.264 | 全機種で再生・保存可 | **無変換**（入れ物だけ整える） |
| HEVC (H.265) | iPhone 7 以降で再生・保存可（`hvc1` タグが必要） | **無変換**＋`hvc1` タグ付け（新規） |
| AV1 | iPhone 15 Pro 以降のみハードウェア再生（ソフト再生なし） | 端末が対応していれば**無変換**、非対応なら H.264 へ変換（新規） |
| VP9 | 写真アプリで扱えない | H.264 へ変換（従来どおり） |

- アプリが端末の再生能力（AV1 / HEVC）を自動判定してサーバーへ伝え、サーバーはそれを見て「そのまま渡す／変換する」を決める
- 画質一覧の表示は「無変換」「要変換」を実際の判定に合わせる

### 9.3 形式選びの不具合修正
- Instagram の H.264 版は yt-dlp 上でコーデック「不明」と表示されるため、これまで VP9 版が優先されて変換が発生していた
- 同じ画質なら「H.264 / HEVC / コーデック不明の mp4」を VP9 より優先して選ぶように修正（不明なものは取得後に中身を確認し、H.264 ならそのまま）

### 9.4 変換が必要な場合の高速化
- Cloud Run の CPU を 1 → **4**、メモリを 2 → **4 GiB** に変更（x264 は複数コアで速くなる。使う CPU 秒の合計はほぼ同じなので費用は大きく変わらない）
- 変換設定（x264 preset）は `veryfast` を維持。実測（VP9 → H.264、1分54秒の動画）：

| preset | 1コア | 4コア | 容量 |
|---|---|---|---|
| veryfast（現在） | 9.0 秒 | 5.8 秒 | 5.3 MB |
| superfast | 8.0 秒 | 5.1 秒 | 9.0 MB |
| ultrafast | 7.6 秒 | 4.5 秒 | 19.2 MB |

  → 速い preset は 1〜2 割しか速くならず容量が 1.7〜3.6 倍になるため不採用
- GPU（Cloud Run の NVIDIA L4）は、常時課金型の設定・利用枠の申請が必要で、個人利用には過剰なため不採用

### 9.5 見送り（将来案）
- iPhone 側のハードウェアエンコーダ（WebCodecs）で変換する案：Safari での VP9 デコード対応が不確実なため今回は見送り
